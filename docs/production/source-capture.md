# 배포 소스와 Git 릴리스 연결

후속 실제 Canary·자동 복귀 및 최신 전체 상태는 [Canary 운영 기록](./2026-11-10-canary-checkpoint.md)을 따른다. 아래 값은 각 단계의 근거다.

후속 실제 Blue/Green 전환·복귀와 최신 Git 식별자는 [Blue/Green 운영 기록](./2026-11-10-blue-green-checkpoint.md)을 따른다. 이전 단계의 값은 당시 근거로 보존한다.

현재 실행본과 Git/image 식별자는 [2026-11-10 운영 기록](./2026-11-10-rollout-scaling-checkpoint.md)을 우선한다. 아래 날짜별 내용은 이전 단계의 기록이다.

2026년 11월 9일, 실제 배포 소스를 재현 가능한 Git 기록으로 보존하는 작업을 진행한다. 추적 이슈는 [#336](https://github.com/AigisAI/AegisAI_v2/issues/336)이며, 원래 작업 폴더와 별도의 worktree에 `release/336-private-java-runtime` 후보를 구성한다. 이 작업은 운영 재배포·DB 변경·비밀 회전·추가 컴퓨팅 생성을 포함하지 않는다.

## 원격 기준과의 차이

확인한 원격 dev는 `3154e31505417e95e1a05c50a5d020e8dba4121d`이며, 006 SAST와 005 배포 계약의 별도 개발 계열이다. 실제 운영 스냅샷의 Git 기준은 `a8e51eb26d082fefe420cb150b43815f09fbbcf7`이다. 기준 이후 원격 변경은 917개 경로이며 현재 작업 파일과 겹치는 경로가 120개다.

현재 dev를 배포 소스로 간주하거나 배포 스냅샷으로 덮어쓰지 않는다. 독립 후보는 원래 배포 기준 커밋에서 시작하며, dev 대상 PR은 통합 검토용 draft로만 취급한다. 원격 006의 외부 qualification 게이트를 통과했다고 표시하거나 우회하지 않는다. 해당 게이트를 실배포 검증으로 대신할 수 없고, 이 비공개 운영도 일반 서비스 적합성 근거가 아니다.

## 포함과 제외

API·공유 코드 120개와 화면 60개는 실제 배포 아카이브와 현재 작업 파일이 바이트 단위로 동일하다. 호스트 묶음은 Python 모듈 7개와 별도 systemd unit으로 구성되며 저장소 경로를 대응시킨다. 실제 사용 중인 기존 화면도 배포본의 일부로 보존한다. 모든 변경을 이번 작업에서 새로 작성했다고 주장하지 않는다.

포함 범위는 배포 아카이브의 앱·분석기·AWS 운영 자산, 관련 테스트와 계약, 현재 문서, 비밀 값이 없는 환경 예시와 CI 구성이다. 사이트 실험, tmp, 브라우저 출력, 자격증명 및 별도 Oracle 수정은 제외한다. 기존 Oracle CD 파일은 기준 커밋 상태를 유지하고, 그 기존 테스트에서는 실제 API Node 버전 22를 확인하도록 필요한 부분만 맞춘다.

Git checkout은 텍스트를 LF로 고정한다. 기존 아카이브의 원시 SHA-256과 Git의 정규화된 소스는 서로 다른 식별자다. 원시 아카이브 해시를 새 Git 아카이브 해시로 바꾸거나 같다고 주장하지 않는다. 파일별 배포 멤버 해시·작업 파일 해시·정규화 대응을 후보의 `docs/production/releases/private-java-20261108.json`에 기록한다.

## 검증과 운영 영향

별도 후보의 CI는 이 릴리스 브랜치 push에서만 추가 실행되며 AWS 배포 작업은 없다. clean checkout에 대해 기본 검증과 전용 PostgreSQL/native 검사를 한 번 수행한다. 기존 폴더의 통과 로그를 새 후보의 hosted CI 성공으로 대신하지 않는다.

배포 중인 컨테이너는 여전히 기존 dirty snapshot에서 빌드된 것이다. 소스를 Git에 보존하고 CI를 통과해도 운영 이미지가 그 커밋으로 자동 재배포되지는 않는다. 실제 재배포는 별도 검토된 릴리스 작업이다. 커밋·PR·CI의 최종 식별자는 검증 후 이 문서에 추가한다.

- CI 대상 SHA가 위 소스 커밋과 일치함을 확인했다. 완료 시각은 2026년 11월 9일 12:26:50 한국 시각이다.
- 실제 배포 코드 188개를 [파일별 소스 대응 기록](./releases/private-java-20261108.json)으로 확인했다.
- 깨끗한 worktree의 Git source archive를 두 번 생성해 같은 해시를 확인했다. 파일은 `private-java-source-feb7628b7672.tar.gz`, SHA-256은 `e19e850a73f2b805b8c94dffe95e55963dcc58df0fa272d2fcb0b552d202b4e7`이다.
- 이 소스 아카이브는 과거 운영 배포 아카이브와 다른 산출물이며 운영에 재배포하지 않았다. 기존 작업 폴더의 브랜치와 미커밋 변경도 유지했다.

PR은 dev와 충돌이 있어 mergeable=false인 draft다. CI 성공은 분리한 소스 후보 자체에 대한 것이며 dev와 병합한 결과에 대한 검증은 아니다. 새 구조를 기존 dev에 덮어쓰거나 006 게이트를 삭제해 충돌을 없애지 않는다. 통합은 API·스키마·인증·실행 명세를 비교하는 후속 설계로 남긴다.

후속 [브랜치 비교](./branch-comparison.md)에서 공통 조상 기준 양쪽 변경 115개 경로와 실제 병합 충돌 106개 파일을 확인했다. 앞서 기록한 120개는 전체 미커밋 작업 폴더와 원격 변경의 겹침이며 실제 병합 충돌 수를 의미하지 않는다.

파일별 JSON의 hostedCiStatusAtCapture는 커밋을 만들 당시의 상태다. 이후 완료된 CI 결과는 위 실행 URL과 대상 SHA로 확인하며, 이미 검증한 소스 커밋을 문서 갱신 때문에 다시 만들지는 않는다.
