# 남은 작업과 적용 범위

최종 갱신: 2026-11-09. 사용자는 Blue/Green·Canary·Kubernetes RollingUpdate·HPA 네 가지를 모두 실제 구현·검증 필수로 지정했다.
후속 사용자 지시로 IaC, GitOps/CD, 공급망 보안, 로그·메트릭·트레이싱을 H1~H4 필수 항목으로 복원했다. G1~G4와 합쳐 총 여덟 항목 모두 미완료다.
실행 계획과 G1~G4·H1~H4 완료 조건은 [기존 실배포 준비 및 운영 검증 계획](../reports/2026-11-07-production-deployment-plan.md)의 4/G·4/H·8·9절을 따른다.
기존 비공개 릴리스는 배포 완료이며, 새 확장 마일스톤은 아직 미완료다. 이번 변경은 문서 갱신이며 서버 변경·신규 자원 생성 승인이 아니다.

## 현재 완료된 기반

- 최신 dev 기반 private 프로필 통합 후보가 CI 두 작업을 통과하고 `ec2-runtime-20261109-054314`로 실제 배포됐다. PR #339는 미병합이며, 일반 dev 계약/DB 및 006 외부 자격 조건은 유지했다.
- 배포 소스는 `ab65d878b7462ccdd8e64d63721a57b20aac62ae`, [CI](https://github.com/AigisAI/AegisAI_v2/actions/runs/42568907973), [배포 태그](https://github.com/AigisAI/AegisAI_v2/tree/deploy/private-ec2-20261109-054314)로 추적한다.
- DB 마이그레이션 6개와 호스트 스캐너 모듈 7개가 보존됐다. 사용자 1·연동 1·선택 저장소 5·완료 스캔 1·스캐너 실행 3·근거 1건이 유지됐다.
- 새 코드의 결과·암호화 근거 조회, 권한 차단, 관리형 비밀 로딩, DB/Redis·브로커·스캐너 준비 상태와 사설 HTTPS를 확인했다. 새 실스캔과 대화형 OAuth는 이번 배포에서 반복하지 않았다.
- 배포 전 암호화 외부 백업·해시·기존 검증 DB 복원을 확인했다. 운영 DB 복원이나 전체 호스트 재구축 완료를 의미하지 않는다.
- 옛 runtime.env 의존성과 관리형 비밀에 대응하는 비활성 사본 3건은 제거됐다. 모든 과거 사본을 제거한 것은 아니다.

네 전략을 한 번의 배포에 동시에 혼용할 필요는 없다. 각각 선택 가능한 실행 경로와 실제 성공·실패 근거가 모두 있어야 확장 완료다.
별도 실험/검증 환경은 중간 검증에 사용할 수 있지만 실제 서비스 적용 완료를 대신하지 않는다.

## 자원·보안·비용 제약

기존 EC2 한 대, 추가 EC2·Fargate·NAT Gateway 금지 조건을 유지한다. EKS나 인스턴스 증설도 자동 승인된 것이 아니다.
자원 부족 또는 적용되는 005/006 자격 게이트가 막으면 실제 차단 요건을 보고하고 필수 항목은 미완료로 둔다.
운영용 Kubernetes 전환 전에 명세·위협 모델·자원·격리·복구 설계를 확정해야 한다. 일반 서비스의 T053~T056 게이트를 삭제하거나 성공으로 바꾸지 않는다.

HPA의 대상은 우선 API이며, DB·Redis·브로커·감독 프로세스와 실제 스캐너를 자동 복제하지 않는다. 실제 무거운 분석은 계속 한 건으로 제한한다.
Blue/Green과 HPA가 같은 호스트의 장애를 해결하거나 노드를 추가하는 것으로 표현하지 않는다. 고객 코드 실행·빌드·패키지 설치 금지와 독립 gVisor 경계를 보존한다.
사용자가 보존하도록 한 이전 EBS·스냅샷은 삭제 완료 조건에서 제외한다. 메트릭·알림 등 추가 사용료가 생기는 작업은 예산 범위를 명시한다.

| 백업·복원 | 지정된 절차 확인 | 전체 DR·정량 RTO/RPO·임의 이미지 롤백은 별도 검증 |
| AI | DISABLED | 현재 분석 사용 가능. 연동은 선택 후속 |

테스트는 변경된 경로와 의미 있는 정상·실패 사례에 한정한다. 단순 문서 변경 때문에 새 스캔·복원·부하 시험이나 기존 전체 코드 검증을 반복하지 않는다.

H1~H4도 G1~G4와 같은 최종 완료 조건이다. 특정 서명 도구·레지스트리·state backend는 권한/비용/호환성 검토 후 확정한다. 이번 추가로 EKS·RDS 등 새 유료 자원이나 SQS 교체를 자동 승인하지 않는다.

관측성은 Grafana·Loki·Prometheus 모두 실제 사용하는 구성이 필수다. OpenTelemetry 추적은 유지하며 trace backend는 별도 선정한다. 배치·보관·비용·자원 조건은 구현 전에 확정하고, 이번 지정만으로 서버 설치나 신규 컴퓨팅 생성을 수행하지 않는다.
